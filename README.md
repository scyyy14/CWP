# 单轨桥吊调度优化（不使用第三方求解器）

本项目解决离散时间、不可交叉且始终保持至少一个空贝位安全间距的 CWP 变种。求解部分完全由 Python 自行实现，不调用 OR-Tools、Gurobi、CPLEX、SCIP、PuLP 等优化求解器；Matplotlib 只用于绘制甘特图。

## 1. 时间与运动语义

桥吊按物理位置从左到右永久编号为 `q=1,...,M`。整数 `t` 表示时间槽 `[t,t+1)` 的左边界：

- 作业：桥吊在 `t`、`t+1` 均位于同一贝位，完成 1 单位作业；
- 移动：输入参数 `move_time` 指定一次任意距离换位占用的时间槽数，默认 `1`；移动期间不能作业；
- 空闲：两个边界位置不变且没有作业。

`move_time=0` 表示瞬时换位：桥吊可在相邻两个作业时段的边界改变位置，移动本身不占时间槽。`move_time=k>0` 表示一次换位连续占用 `k` 个时间槽；多台桥吊可以并行移动，程序以端点间线性轨迹检查全过程安全间距。为避免把旧实例悄悄改义，未提供该字段时仍按 `1` 处理。当前完整最优性证明只适用于 `move_time=1`；其他取值输出经过独立校验的启发式可行解，不宣称最优。正整数移动展开期间，未移动桥吊在额外展开槽中保守地记为空闲。

所有合法位置组合均满足 `p(q+1,t)-p(q,t)>=2`。两个合法位置组合之间采用线性移动时，相对距离是端点距离的线性插值，因此整个移动槽内也始终不小于 2；永久编号同时排除了桥吊交叉。

## 2. 数学问题定义

模型用于严格描述问题，但程序不会把模型提交给任何求解器。

### 变量

- `p_qt in {1,...,N}`：桥吊 `q` 在整数边界 `t` 的位置；
- `x_qit in {0,1}`：桥吊 `q` 是否在槽 `t` 于贝位 `i` 作业；
- `m_qt,e_qt in {0,1}`：桥吊是否移动、空闲；
- `u_qi in {0,1}`：贝位 `i` 是否由桥吊 `q` 参与作业；
- `L_q=sum(i,t)x_qit`：桥吊累计负荷；
- `C_max`：整体完工时间。

### 约束

1. 安全与顺序：`p_(q+1,t)>=p_qt+2`；
2. 移动定义：`m_qt=1 <=> p_q,t+1!=p_qt`；
3. 唯一状态：`sum_i x_qit+m_qt+e_qt=1`；
4. 原地作业：`x_qit=1 => p_qt=p_q,t+1=i`；
5. 作业量守恒：`sum(q,t)x_qit=W_i`；
6. 贝位互斥：`sum_q x_qit<=1`；
7. 强制开工：`sum_q x_q,i,0=1, i in S`；
8. 完工时间：`C_max>=(t+1)x_qit`。

四项目标按词典序比较：完工时间、拆分贝位数、移动次数、中间重载偏差。先尽快完成，再尽量让每个贝位只由一台桥吊作业，然后减少桥吊移动，最后偏好中间吊多作业、两边吊少作业。中间重载使用对称权重 `w_q=min(q+1,M-q)`（q 从 0 开始），六台吊为 `1:2:3:3:2:1`；偏差为 `sum_q |sum(w)*load_q-total_work*w_q|`，越小越好。拆分贝位数统计由超过一台吊作业的贝位数量。

桥吊—贝位分配数和折返次数仅保留为统计信息，不参与最终方案比较。折返定义为同一台桥吊相邻两次移动方向发生改变；作业或空闲不会清除其上一次移动方向。构造阶段的局部派工分数仍用于探索，完整候选的接受、精英池排序和发布统一按上述四目标比较；启发式搜索不保证次级目标全局最优。

## 3. 自定义搜索方法

程序使用自行实现的“优先级解码 + 动态分区种子 + 自适应搜索 + 限宽分层动态规划 + 精确分支定界”：

1. 合法位置总数不超过 20000 时完整枚举；超过时用强制位置约束下的加权独立集动态规划生成最多 128 个初始候选。派工仍可访问全部物理可达贝位；下界单独在完整位置域上求解，不以候选池代替完整空间；
2. 从满足 `S` 的多个初始位置组合出发；
3. 按连续贝区的工作密度计算拥挤优先级，让关键瓶颈贝区更早获得桥吊；
4. 每槽用前缀最大值动态规划选择最佳安全组合；桥吊数不超过 3 时，前 300 轮用 DP，随后切回旧聚焦组合解码器及其联合随机扰动，保留不同搜索路径；
5. 同时保留原始规则与拥挤优先规则，并用 UCB 自适应选择机制把更多搜索次数分配给当前实例上表现更好的规则；连续长时间没有改进时会自动加强探索；
6. 使用满足 `S` 的多个高负荷初始位置反复构造排程，并从当前最好方案继承、删除或变异部分贝位归属，再由安全解码器修复；
7. 保存最多 16 个结构不同的完整精英方案（贝位归属和移动路线不同），轮换从这些方案开始做工期压缩；相同结构的新方案若目标更好会替换旧成员，当前全局最好方案始终被保留；
8. 对最后完工桥吊两侧的有效邻居链建立晚期局部窗口。调用方把同一个窗口和来源方案传给局部束搜索；删除的时间边界只能位于窗口内，束搜索必须走完整窗口并在安全出口接回固定轨迹，未完成的束层直接丢弃；
9. 对所有可行排程按四项目标进行严格词典序比较：工期、拆分贝位数、移动次数、中间重载偏差；
10. 输出前调用独立校验器，再次检查作业量、强制开工、状态一致性、安全间距和贝位互斥。

预算至少 2 秒且 M > 3 时，多策略构造使用 5～12 秒（随总预算增加，且不越过整体 deadline），给大实例更多独立初始方案；M <= 3 时构造至多 15 秒、不超过预算的 90%，给两种解码器更多机会。随后把剩余改进预算的 65% 分给完整轨迹修复：先删除一个时间边界，把目标工期缩短 1，再移动或合并单台桥吊的作业区段。修复状态保存当前轨迹、缺口、最好轨迹和随机数状态，时间片结束后可在相同来源方案上继续。修复过程中始终满足安全间距与强制首槽作业，可以暂时缺少作业量；通过增量统计缺口和退火接受规则跳出局部最优，只有全部作业完成才接受为新方案。

余下时间交给部分排程 MCTS、四次限宽分层重排及选择性精确搜索。达到理论下界后不再搜索更短工期；构造阶段仅允许至多 64 次连续未改进的次级目标优化。精确搜索仅在工期差距不超过 1、合法位置组合不超过 20000 时启用。限宽搜索、动态规划派工、轨迹修复本身都不能证明全局最优。

四次分层搜索各自获得独立的阶段时间份额，防止第一次全局搜索耗尽全部预算。连续分区种子还会生成两档开放边界版本；即使分区之间夹着零工作贝位，也能找到两侧最近的有工作贝位，让相邻桥吊按不同工作量接续处理。桥吊较多、每台只能保留极少候选位置时，程序会在高价值作业贝位、当前最好方案引导、探索贝位和边界停车位之间轮换。

该方法不依赖求解器，能够持续改进可行解，但一般情况下不能像 CP-SAT/MILP 一样证明完整词典序全局最优。

程序计算六类完工时间理论下界：

```text
LB_single = max_i W_i
LB_work   = ceil(sum_i W_i / M)
LB_active = ceil((sum_i W_i + move_time * minimum_required_moves) / M)
LB_window = max over every contiguous window B:
            ceil(sum(i in B) W_i / min(M, ceil(|B|/2)))
LB_window_active = max over every contiguous window B:
                   ceil((work in B + minimum arrivals into unfinished bays in B)
                        / min(M, ceil(|B|/2)))
LB_eligible = max over every contiguous crane subset Q:
              ceil((work forced onto Q + move_time * minimum first-visit moves) / |Q|)
LB = max(LB_single, LB_work, LB_active, LB_window,
         LB_window_active, LB_eligible)
```

`LB_active` 把访问不同作业贝位所必需的最低移动次数计入桥吊总活动时间；`LB_window` 利用安全间距约束——长度为 `L` 的连续贝区同时最多容纳 `ceil(L/2)` 台正在作业的桥吊；`LB_window_active` 进一步计入这些贝位所需的最低首次到达次数；`LB_eligible` 检查每一段连续桥吊编号，统计由于不可交叉而只能由这组桥吊完成的工作和最低移动量。它们都只增强证明能力，不会排除任何合法排程。

如果构造解的完工时间等于 `LB`，则输出 `MAKESPAN_OPTIMAL_BY_LOWER_BOUND`；如果完整分支定界排除了所有更短工期，则输出 `MAKESPAN_OPTIMAL_BY_EXACT_SEARCH`。两者都证明完工时间全局最优，但拆分、负荷等次级目标仍只表示当前搜索到的最好结果。精确搜索超时且未达到下界时输出 `HEURISTIC_FEASIBLE`，不会误报最优。

## 4. 安装与运行

建议使用 Python 3.10+：

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python cwp_solver.py
```

输入格式：

```json
{
  "W": [4, 2, 0, 5, 3, 4, 1, 3, 2, 4],
  "M": 3,
  "S": [2, 6],
  "move_time": 1
}
```

`move_time` 是可选的非负整数。导师版本移动不耗时时填 `0`；省略时为 `1`，与原项目完全相同。

输出：

- `output/schedule.json`：算法状态、理论下界、折返/移动次数、各贝位归属和逐时间槽状态；同时记录 `phase_seconds` 与 `operator_calls`，可查看各搜索阶段的实际耗时和调用次数；
- `output/schedule.png`：横轴为 1-based 贝位序号、纵轴为时间。实心格为作业，虚线箭头为移动，空心点为空闲。

参数：

- `--restarts K`：最多执行的构造搜索轮数，默认 100000，实际还受时间和早停条件限制；
- `--time-limit SEC`：CLI 使用 `solve_cwp_bounded()` 独立子进程限时，封顶 270 秒，包含预处理；每次更优可行解先校验再原子保存，子进程超时后取回最近完整结果。主程序预留约 30 秒用于校验和输出，PNG 最多运行 25 秒。极短预算若尚无完整结果会明确报超时。直接调用 `solve_cwp()` 仅有协作式截止检查，不能替代进程限时。
- `--patience K`：达到完工时间下界后，连续 `min(K, 64)` 次未改进次级目标即停止构造；
- `--seed VALUE`：固定随机数序列；按墙钟时间截断时，机器负载仍可能影响迭代数及最终结果。
- 不带任何参数运行时自动读取 `example_input.json`、写入 `output`，搜索上限为 270 秒；只有需要覆盖默认值时才填写参数。
- 默认保存图片后调用 `plt.show()` 弹出甘特图；服务器或无图形界面运行时加入 `--no-show`。
- `--show`：保存后显示图片（默认开启）；窗口等待用户关闭的时间不计入计算预算。
- 第一次绘图会建立 `output/.matplotlib-cache`；后续运行复用字体缓存，明显减少 Matplotlib 启动时间。
